Trade Scope Platform

Role Product / UX-UI Design
Platform Web & Mobile
Focus Venture portfolio analytics
img-2.webp

A venture investor's portfolio rarely lives in one place. Crypto sits in Binance, positions sit with a broker, and the rest lives in a spreadsheet nobody trusts. Trade Scope pulls all of it into a single, calm interface — so tracking performance stops being a second job.

The brief was to design a CRM-style platform for venture and crypto investors who manage several wallets and strategies at once. It had to connect directly to exchanges and brokers, stay legible at a glance, and still hold up when someone needs to dig into a single trade at 2am.

Goals of the Platform

  1. 01 Simplified Portfolio Management: Centralizes stocks, cryptocurrencies, and other assets in one platform instead of five tabs.
  2. 02 Integrated Data Sources: Connects to Binance, Interactive Brokers, and manual entries for a complete asset view.
  3. 03 Actionable Insights: Real-time metrics, historical trends, and AI-driven forecasts, not just raw numbers.
  4. 04 Customizable User Experience: Personalized wallets and dashboards tailored to each strategy — long-term, scalping, intraday.
  5. 05 Secure API Connections: Broker integration with scoped access (read-only vs. trading) and IP restrictions.
  6. 06 Collaboration & Sharing: Portfolio sharing and real-time updates among teams and stakeholders.
Process

Mapping the Flow First

Before touching a single screen, I mapped how a user actually moves through the product: sign up, land on the dashboard, connect an exchange, spin up a wallet per strategy, then pull a report out of it. That flow became the backbone for every navigation decision that followed — it's the reason "create a wallet" and "manage a wallet" never got tangled into one confusing screen.

img-3.webp

Early flow map: onboarding branches into a dashboard hub, which fans out to notifications, API connections, wallets, and reporting — with the Trading Academy and community as parallel, always-reachable exits.

Sign Up

img-4.webp

A short registration form paired with a preview of the dashboard the user is about to unlock — the product sells itself before the account even exists.

Dashboard Overview

img-5.webp

One screen, four wallets, no scrolling to find out if you're up or down today. A donut for allocation, a line for trend, a table for the trades that actually moved the needle.

The hardest constraint wasn't fitting data on screen — it was deciding what earned a place on it. Every wallet strategy has its own rhythm; the dashboard had to respect that instead of averaging it away.

API Connections

img-11.webp

Entry point for every integration: pick an exchange (Binance, Coinbase, Kraken, KuCoin, Bybit), see every key already issued with its access level and creation date, and a plain-language "How does it work" panel for anyone connecting an API for the first time.

Generate & Secure an API Key

img-6.webp

Naming keys by purpose ("Trading Bot Key," "Main Binance Account") instead of leaving them anonymous — small detail, but it's what stops someone from revoking the wrong one at 2am.

img-7.webp

Access is scoped before the key exists, not after: Read-only or Trading, with an optional IP lock. The secret key is shown once, with an explicit warning — never stored in a way the user can retrieve casually.

Web + Mobile parity

Create a Wallet

A "wallet" here isn't a crypto address — it's a strategy container: Long-term, Scalping, Intraday, whatever the investor is running. Creating one takes the same two-tier pattern as the API key screen (basic settings, then advanced), so the product only teaches this pattern once.

img-8.webp

Name, type, category tag, and currency up front; color, spend limits, and API linking tucked under "Advanced" so a first-time user isn't blocked by decisions they don't have yet.

img-9.webp

The same wallet flow, unmodified on mobile — because a strategy idea doesn't wait for a desktop.

img-10.webp

Confirmation doubles as a next step: edit the wallet, connect an API, or jump straight to the dashboard — no dead end after the "success" moment.

Wallet Management

img-12.webp

Every wallet gets its own color and its own "today" — a Scalping wallet up 1% reads completely differently from a Long-term wallet up 1%, so they're never compared on the same axis.

img-13.webp

Drilling into one wallet: allocation, trend, and every open position with its stop-loss / take-profit — plus a sidebar for exporting and reading ROI without leaving the page.

img-14.webp

Two wallets, side by side, same layout mirrored left and right — the question "which strategy is actually working?" gets a visual answer instead of a mental one.

Reporting Tool

img-15.webp

Filter by date, wallet, and condition; pick exactly which columns matter (wallet details, asset details, performance); export to CSV, Excel, or PDF. Built for the investor who needs to hand numbers to an accountant, not just look at them.

img-16.webp

The full navigation — Reporting, Wallets, API connections, Settings — collapses into one mobile menu without losing a single wallet or shortcut from the desktop version.

Reflection

What Held It Together

Mapping the flow before the screens is what kept "create a wallet" from bleeding into "manage a wallet," and what made the mobile screens a genuine port of the desktop product rather than a stripped-down cousin. In a domain this data-dense, the interesting design problem was never how to fit more on screen — it was knowing what to leave off it.
